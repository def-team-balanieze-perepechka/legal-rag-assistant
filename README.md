# legal-rag-assistant

Юридический ассистент по базе знаний компании (Hack&Change 2026, кейс ПСБ). Отвечает строго по документам базы, ссылается на конкретные пункты и честно отказывает, когда в базе нет достаточных сведений.

Состав решения:

- `core/` — агент: роутер вопроса, гибридный поиск, генерация, проверка цитат;
- `solution.py` — точка входа платформы (`questions.csv` + база → `submission.csv`);
- `api/` — HTTP-бэкенд (FastAPI) поверх `core/`;
- `ui/` — веб-чат (Streamlit) с просмотром документов и подтверждающих фрагментов;
- `eval/`, `scripts/` — тесты, локальный судья, сборка сабмита.

## Архитектура: роутер + гибридный RAG со строгими цитатами

```
вопрос ──► разбор диалога ──► роутер ─────► поиск ──────────────────────────────► генерация ──► проверка ──► ответ
                              (1 вызов LLM) BM25 (свой стеммер)  ┐                (1 вызов LLM)   кодом
                              сценарий,     bge-m3 /embeddings   ├─ RRF ─► /rerank JSON с         chunk_id только из
                              документы,    сущности: № договора,┘                  chunk_id       найденных фрагментов;
                              запросы,      контрагент → документ целиком;                         ссылку «Источник: …»
                              дата события  другие редакции пункта; допсоглашения                  собирает код
```

**Роутер** (`core/router.py`) один раз просит LLM составить план вопроса: сценарий (`fact`, `false_premise`, `date_edition`, `multi_doc`, `not_in_kb`, `illegal`, `offtopic`, `old_law`), нужные документы из каталога базы, до трех поисковых запросов, дату события и проверяемые утверждения. План сужает поиск и подсказывает генератору, как отвечать: ошибочную предпосылку — поправить, редакцию — выбрать по дате события, противоправный запрос — не выполнять, а объяснить требования закона. `ROUTER=0` отключает роутер, и агент работает одним вызовом на вопрос.

| Модуль (`core/`) | Что делает                                                                                                                                                                |
|------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `kb.py`          | разбор базы (TXT/MD/DOCX, DOCX читается без сторонних библиотек): чистка Гаранта, чанки по пунктам и частям, редакции, допсоглашения, справочник договоров и контрагентов |
| `stem.py`        | токенизация и стеммер русского для BM25                                                                                                                                   |
| `search.py`      | BM25 + эмбеддинги -> RRF -> реранкер; распознавание договоров и контрагентов                                                                                              |
| `router.py`      | план вопроса: сценарий, документы, запросы, дата события                                                                                                                  |
| `llm.py`         | клиент прокси: `/chat/completions`, `/embeddings`, `/rerank`, повторы, отключение недоступных сервисов                                                                    |
| `prompts.py`     | системный промпт и шаблоны                                                                                                                                                |
| `generate.py`    | вызов LLM, разбор JSON, отбрасывание неизвестных `chunk_id`, ссылка на источник                                                                                           |
| `checks.py`      | проверки после генерации: несуществующие статьи, утекшие `chunk_id`                                                                                                      |
| `assistant.py`   | `Assistant.answer(question, history=None, allow_clarify=False) -> dict`                                                                                                   |

Если эмбеддер или реранкер недоступны, поиск продолжается на BM25 и RRF. Если модель дважды не выдала JSON (обрыв по лимиту, сломанный формат), делается запасной вызов: короткий промпт без JSON по 3 лучшим фрагментам (`LLM_NO_THINK=1` — без рассуждений для qwen3). Если не отвечает LLM, ассистент честно сообщает, что ответ сформировать не удалось; ошибка одного вопроса не роняет прогон.

Проверки после генерации (кодом): ссылки на пункты, которых нет среди переданных модели фрагментов, удаляются; к отказам («нет в базе», вне темы, противоправный запрос) подпись «Источник:» не добавляется. У статей закона есть тема-налог (НДС / НДФЛ / налог на прибыль), определенная по тексту: она входит в индекс и в заголовок фрагмента, а если в вопросе назван налог, статьи о других налогах из выдачи убираются.

## Веб-интерфейс и API

**Чат** (`ui/`, Streamlit). Пользователь задает вопрос, диалог учитывается при следующих репликах. У каждого ответа есть кнопка «Источники»: справа открывается панель с цитатами, на которые опирается ответ. По клику на цитату открывается документ с подсветкой нужного фрагмента (короткий режим с контекстом или документ целиком). В боковой панели — каталог документов базы по типам (договоры, допсоглашения, законы, регламенты и др.). UI обращается только к API и не получает ключ LLM.

**API** (`api/`, FastAPI):

| Метод и путь              | Назначение                                                           |
|---------------------------|----------------------------------------------------------------------|
| `GET /health`             | состояние сервиса и базы знаний: 503 пока база грузится, затем 200   |
| `GET /documents`          | каталог документов для UI                                            |
| `GET /documents/{doc_id}` | полный текст документа                                               |
| `POST /chat`              | вопрос или диалог (`messages` > `question` + `history` > `question`) |

При старте база загружается из `KB_PATH` либо из `DATA_DIR/knowledge-base.zip`. Swagger: `/docs`.

Локальный запуск без Docker:

```bash
pip install -r requirements-api.txt -r requirements-ui.txt
cp .env.example .env                       # Без Docker: LLM_BASE_URL=http://localhost:11434/v1 (для Ollama), LLM_API_KEY, LLM_MODEL
uvicorn api.main:app --port 8001           # API: http://localhost:8001, Swagger: /docs
API_URL=http://localhost:8001 streamlit run ui/app.py
```

## Запуск без Docker

```bash
pip install -r requirements.txt pytest python-dotenv
cp .env.example .env        # без Docker: LLM_BASE_URL=http://localhost:11434/v1 (для Ollama), LLM_API_KEY, LLM_MODEL
python solution.py          # DATA_DIR/questions.csv + база -> submission.csv
python eval/run_demo.py     # Демо-вопросы -> out/demo_report.md (ответ рядом с эталоном)
python -m pytest eval       # Тесты без сети
python scripts/build_submission.py   # dist/submission.zip, все файлы в корне архива
```

Локально через Ollama: `ollama pull qwen3:4b` и `ollama pull bge-m3`, настройки — в конце `.env.example`. Реранкера в Ollama нет: без `DEV_RERANK_BASE_URL` поиск работает без него.

## Локальный судья

Сравнивает версию агента с baseline (стартовый `solution.py` из `data/sample_submission.zip`) по методике платформы: попарно с опорой на эталон, два раунда со сменой порядка, `Score = 0.7·MatchRate + 0.3·WinRate`, выдуманный факт — 0 за вопрос; заглушка агента — 0 без вызова судьи. Кейсы: демо из `data/` и свои из `eval/cases_own.csv`.

```bash
python eval/judge.py --name v1 --checks-only   # Только ответы агента и проверки кодом (заглушки, несуществующие пункты, ложные отказы)
python eval/judge.py --name v1                 # Полный прогон: агент, baseline, судья, отчет
```

- Отчет: `out/eval/<name>/report.md`, история прогонов: `out/eval/history.csv` (разница с прошлым прогоном на том же наборе кейсов).
- Ответы и вердикты кешируются: повторный запуск с тем же `--name` не вызывает LLM; для новой версии агента — новое `--name`.
- Фильтры: `--ids demo-5 own-3`, `--scenario false_premise`, `--source demo|own`.
- Судья: `JUDGE_MODEL` (по умолчанию `qwen3:8b`), `JUDGE_BASE_URL` / `JUDGE_API_KEY` (по умолчанию как у агента), `JUDGE_MAX_TOKENS` (8192: qwen3:8b с 4096 иногда не успевает дорассуждать), `JUDGE_TIMEOUT` (600 с). На локальной Ollama генератор и эмбеддер выгружаются перед фазой судьи. Baseline запускается пачками по 10 вопросов без настроек агента из `.env` (`TOP_K` и т. п.), с лимитом `BASELINE_MAX_TOKENS` (по умолчанию 4096: с 1024 локальная qwen3 не успевает ответить).
- Ограничение: наш судья не совпадает с судьей платформы.

## Запуск через Docker

Проект поддерживает два режима работы в Docker:

1. **Веб-интерфейс (UI + API)** — интерактивный ассистент для работы с базой знаний в браузере.
2. **Пакетный прогон (Solution)** — фоновая обработка файла `questions.csv` для генерации `submission.csv` (используется для сдачи на платформе или массового тестирования).

Для изоляции зависимостей проект использует три файла `requirements`: `requirements.txt` для solution, `requirements-api.txt` для API, `requirements-ui.txt` для UI.

### Требования

- **Docker** с **Compose ≥ 2.24** (нужен для `env_file: required: false`). Проверка: `docker compose version`.
- **Ollama** или **любой OpenAI-совместимый API** на хосте (см. раздел «Внешние API»).
- Для локальной Ollama — скачанные модели (см. раздел «Ollama на хосте»).

### Подготовка окружения

1. Скопируйте шаблон окружения:

   ```bash
   cp .env.example .env
   ```

2. Создайте каталоги для входа и результата:

   ```bash
   mkdir -p data out
   ```

3. Проверьте в `.env` адрес и ключ LLM. Шаблон уже настроен на Docker и Ollama на хосте (`LLM_BASE_URL=http://host.docker.internal:11434/v1`, `LLM_API_KEY=ollama`): внутри контейнера `localhost` — это сам контейнер, поэтому до хоста обращаются по `host.docker.internal`. Для внешнего API (например, DeepSeek) подставьте его `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. Остальные переменные можно не менять. Переменная `DATA_DIR` в контейнерах задается в `compose.yaml` (`/data`), значение из `.env` на нее не влияет.

На Linux/WSL — чтобы контейнер писал в `./out` от вашего пользователя, а не от `root`:

```bash
export LOCAL_UID=$(id -u)
export LOCAL_GID=$(id -g)
```

Положите входные данные в `data/`:
- `data/knowledge-base.zip` (база знаний, общая для всех команд, в репозиторий не входит);
- `data/questions.csv` (для пакетного режима).

### Режим 1: Запуск всего решения (Веб-интерфейс + API)

В этом режиме поднимаются контейнеры `ui` (Streamlit) и `api` (FastAPI).

```bash
# Сборка и запуск UI + API (по умолчанию)
docker compose up --build
```

После запуска:
- **Веб-интерфейс:** `http://localhost:8000`.
- **API бэкенд:** только с вашей машины, `http://127.0.0.1:8001` (Swagger: `/docs`).

API начнет отвечать только после загрузки базы знаний (Docker healthcheck ждет ответа `/health`), UI стартует после него. Чтобы остановить все, нажмите `Ctrl+C` или выполните `docker compose down`.

### Режим 2: Пакетный прогон (только Solution)

Если нужно обработать `questions.csv` и получить `submission.csv`, UI и API запускать не обязательно. Сервис `solution` находится в профиле `batch` и запускается по требованию.

```bash
# Сборка и запуск только solution
docker compose --profile batch run --rm solution
```

Флаг `--rm` удалит контейнер после завершения скрипта. Результат появится в `out/submission.csv`. В логах — загрузка базы знаний, инициализация LLM и прогресс обработки вопросов (каждые 10 штук).

### Переменные окружения

Шаблон — `.env.example`. Скопируйте его в `.env` и при необходимости поправьте. В колонке «По умолчанию» — значения из `.env.example`.

| Переменная        | Назначение                                                                                    | По умолчанию                           |
|:------------------|:----------------------------------------------------------------------------------------------|:---------------------------------------|
| `LLM_BASE_URL`    | Адрес OpenAI-совместимого API (без Docker для локальной Ollama — `http://localhost:11434/v1`) | `http://host.docker.internal:11434/v1` |
| `LLM_API_KEY`     | Ключ (для локальной Ollama — любое непустое значение)                                         | `ollama`                               |
| `LLM_MODEL`       | Имя модели LLM                                                                                | `qwen3:4b`                             |
| `EMB_MODEL`       | Модель эмбеддингов                                                                            | `bge-m3`                               |
| `RERANKER_MODEL`  | Модель реранкера (пусто — отключен)                                                           |                                        |
| `TOP_K`           | Сколько чанков брать в контекст                                                               | `8`                                    |
| `TEMPERATURE`     | Температура генерации                                                                         | `0`                                    |
| `MAX_TOKENS`      | Лимит токенов ответа                                                                          | `2048`                                 |
| `MAX_WORKERS`     | Параллельные запросы (для solution)                                                           | `1`                                    |
| `TIME_BUDGET_SEC` | Бюджет прогона solution, в секундах                                                           | `900`                                  |
| `LLM_TIMEOUT`     | Таймаут одного запроса к LLM, в секундах                                                      | `300`                                  |
| `CHAT_TIMEOUT`    | Таймаут запроса в UI/API, в секундах (в compose: API 270, UI 300)                             | не задан                               |
| `DATA_DIR`        | Каталог с `knowledge-base.zip` и `questions.csv` (в Docker — `/data`, задается в compose)     | `data`                                 |
| `API_URL`         | Адрес API для UI (задается в compose)                                                         | `http://api:8000`                      |

Дополнительно поддерживаются `ROUTER` (`0` — без роутера), `KB_PATH`, `LLM_EXTRA_BODY`, `LLM_NO_THINK`, `DEV_EMBED_BASE_URL`, `DEV_RERANK_BASE_URL`, `EMBEDDER_API_KEY`, `RERANKER_API_KEY`.

### Внешние API

На платформе используются:

| Компонент                | Сервис / модель     | Переменная                                 |
|:-------------------------|:--------------------|:-------------------------------------------|
| LLM                      | DeepSeek V4.1 Flash | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |
| Эмбеддинги               | BAAI/bge-m3         | `EMB_MODEL`                                |
| Реранкер (необязательно) | Qwen3 Reranker 8B   | `RERANKER_MODEL`                           |

Ключей в репозитории нет. Чтобы подключить внешний API, укажите в `.env` его `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`; ключ хранится только в `.env`, который не попадает в git.

### Порты

- **8000** — веб-интерфейс (Streamlit).
- **8001** — API (FastAPI). Доступен только на `127.0.0.1` (`localhost`), чтобы не светить ключ LLM в сеть: у API нет авторизации.

### Зависимости

Версии зафиксированы. Три файла нужны, чтобы Docker собирал легкие образы:
- `requirements.txt` — для solution (`numpy`, `rank-bm25`, `httpx`); `python-dotenv` для локального запуска ставится отдельно, на платформе не нужен;
- `requirements-api.txt` — для бэкенда (`fastapi`, `uvicorn`, `pydantic`, `python-dotenv`, `httpx`, `numpy`, `rank-bm25`);
- `requirements-ui.txt` — для фронтенда (`streamlit`, `httpx`).

`Dockerfile` использует `ARG REQS` для установки нужного набора пакетов в каждый сервис.

```bash

```

  - В логах API: `Application startup complete` и `Uvicorn running on http://0.0.0.0:8000`.
  - В логах UI: `You can now view your Streamlit app`.
  - В браузере на `http://localhost:8000` открывается чат. Задайте вопрос по базе, например про условия договора: в ответе есть ссылка «Источник», по кнопке «Источники» справа открываются цитаты, по клику на цитату — документ с подсветкой фрагмента. На вопрос вне базы ассистент должен отказать и объяснить, чего не хватает.

**Пакетный прогон:**

docker compose --profile batch run --rm solution

### Ollama на хосте

Ollama доступна из контейнера по имени `host.docker.internal` (в `compose.yaml` прописан `extra_hosts: ["host.docker.internal:host-gateway"]`); адрес нужно указать в `LLM_BASE_URL`, см. «Подготовка окружения».

Скачайте модели:

```bash
ollama pull qwen3:4b   # LLM_MODEL
ollama pull bge-m3     # EMB_MODEL
```

Ollama должна слушать не только `127.0.0.1`, иначе из контейнера до нее не достучаться:
- **Windows:** `setx OLLAMA_HOST "0.0.0.0:11434"` и `setx OLLAMA_CONTEXT_LENGTH 8192`, затем перезапустите Ollama.
- **Linux (systemd):** отредактируйте `systemctl edit ollama`, добавив `Environment="OLLAMA_HOST=0.0.0.0:11434"` и `Environment="OLLAMA_CONTEXT_LENGTH=8192"`.

### Известные ограничения

- **Индекс строится заново при каждом запуске.** `solution.py` и API делают вызовы `/embeddings` к `EMB_MODEL`, это занимает время. Между запусками индекс не кешируется.
- **Без эмбеддера поиск работает только на BM25.** Если `EMB_MODEL` недоступен, система деградирует до BM25 (`dense=False` в логе), но продолжает работать.
- **Без реранкера поиск работает без него.** Для локальной Ollama `RERANKER_MODEL` оставляйте пустым.
- **Ответы на локальной модели хуже, чем на платформенной.** `qwen3:4b` — компромисс по размеру; на платформе используется DeepSeek V4.1 Flash.
- **База знаний не входит в репозиторий.** Файл `data/knowledge-base.zip` нужно положить вручную.
- **Права на `out/` (Linux/WSL).** Контейнер работает от пользователя `LOCAL_UID:LOCAL_GID`. Если не делали `export LOCAL_UID=$(id -u)`, прогон может упасть с `PermissionError`.
- **У API нет авторизации.** Поэтому порт 8001 открыт только на `127.0.0.1`.
